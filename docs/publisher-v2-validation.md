# Publisher V2 交付与验证记录

## 实现范围

- React + Tiptap 替代 CodeMirror，编辑区直接应用模板；桌面/手机共用 UI，编辑器按需加载。
- 属性级文字/段落/标题/图片覆盖、人工样式标识、单属性与全部恢复模板。
- 新建文章、纯 Markdown 导入、ZIP 图片内容包导入；保留人工 GitHub ingest 兼容接口。
- 每篇一个工作稿，2 秒防抖自动保存、手动保存与正式版本分离。修订号和串行保存队列保护多窗口/慢网络下的修改。
- 版本只读、模板 CSS 和素材引用冻结，旧版本复制成工作稿。保留原 Markdown，SQLite 添加字段/表迁移，禁止删除重建。
- 图片选择/粘贴/拖放/替换/删除正文引用、说明、封面、宽度/对齐/圆角；永久删除保护引用，备份覆盖尚未生成版本的素材。
- 先生成并存储最终微信 HTML/图片地址，再由用户确认发送同一产物；发送哈希校验，重复或不确定提交保护；微信返回预览和 HTML diff。
- 保留登录、权限、管理、CSRF、Origin、审计和管理员正式发布确认。
- 内容变化不触发完整软件 CI；GHCR 构建发布与腾讯云拉取部署工作流；digest 固定、停止写入后备份、容器健康检查和数据库/镜像一起回退。

## 本地验证

- `python -m pytest -q`：28 passed，15 subtests passed（包含现有播客回归）。
- `npm run test:browser`：5 个浏览器验收场景：保存/刷新/历史版本/局部样式/手机布局；图片与微信确认；冲突重新读取；导航期间停止编辑；版本保存期间另一窗口修改。
- `npm run build`：成功；登录主包约 201KB，编辑器按需包约 487KB。
- Docker 构建（`PUBLISHER_BASE_PATH=/publisher/`）：成功；非 root、只读文件系统、tmpfs 数据目录启动，healthz 和前端子路径资源检查通过。
- 真实 `pull-publisher.sh` 在隔离容器中以模拟 Docker CLI 运行：成功路径通过；启动失败后数据库与旧镜像恢复通过。这不代表腾讯云已经部署。
- 工作流 YAML 解析、Compose（示例环境文件）、部署 Bash 语法、Python 未定义名称检查、Git whitespace 检查通过。
- 独立代码审查发现并修复列表/表格迁移丢字、图片路径编码、导航编辑丢失、冲突重读、慢请求保存竞态和跨窗口版本修订号问题；补充对应回归测试。
- GitHub 首轮浏览器检查暴露测试等待竞态：新建文章后旧编辑器仍挂载，测试提前输入。增加新文章标题、可编辑状态和加载完成断言，并在新建请求中注入 1.2 秒延迟覆盖此场景。

浏览器/微信接口验收使用临时数据库和模拟 WeChat，不会发送或发布真实公众号文章。Android 原生 WebView 本机不可实测；上线后需在实际设备检查文件选择、软键盘和排版。

## 首页、历史与重复 GitHub 导入修复

- 初始进入文章首页；编辑页面可返回首页，保留当前页面尚未保存的修改。文章卡片和选择器显示文章编号、目录和版本数量，区分同名文章。
- 历史版本切换无需先保存工作稿。含链接的编辑内容接受 Tiptap 原生 `title` 属性，链接标题经过校验与 HTML 转义。
- GitHub 以文章目录（slug）归组，同一目录更新生成新的历史版本，不同目录允许标题相同。文章列表每 30 秒及窗口重新获得焦点时刷新。
- 未修改且跟随最新版本的工作稿在重新打开时同步新版本；本地修改与主动恢复的旧版本保持不变。页面可明确选择“载入最新版本”，恢复操作串行执行并暂停编辑。
- 升级保留所有已有工作稿，避免误覆盖旧版恢复过的历史内容；如有新版本，通过上述按钮手动载入。数据库只添加字段。
- 验证：Publisher 后端 29 个测试、9 个浏览器场景及前端生产构建。回归覆盖保存失败仍能看历史、同标题列表、重复 GitHub 导入、旧数据库迁移、返回首页保留修改，以及延迟恢复期间禁止输入。

## 生产状态与操作

本次准备的是代码和可执行镜像部署流程。此环境没有腾讯云 SSH 凭据，没有执行生产数据迁移、容器更新或真实微信接口调用。GitHub 中的构建与部署执行记录应作为独立证据。

合入 main 后镜像工作流测试并发布 GHCR；配置 `tencent-production` SSH Secrets，以及服务器 GHCR 公共访问或 read:packages 登录，再手动运行部署工作流并填写已构建的完整 commit SHA。见 [部署说明](../deploy/PUBLISHER-IMAGE-DEPLOYMENT.md)。
